# 球拍类项目的球员发球约定（网球、羽毛球、乒乓球）

2026-10-07 定（协调方决定）。三项运动的发球接口尽量一致：同一个抛球动作、同一组状态字段、同一种计时和犯规记法。
各项运动在 `sport.toml` 里写明自己的合法抛球区域、高度范围、击球约束和处罚，以及对应的规则书条文和偏离。

## 1. 抛球动作

```json
{"type": "toss", "pos": [x, y, z], "height": H}
```

- 球（或羽毛球）在 `pos`（选手自己的坐标系）出现，然后竖直向上抛出，升到 `pos` 上方 H 米处再落下；H = 0 表示从静止
  放下。不加旋转。
- `pos` 必须在该项目合法的抛球区域内，H 必须在该项目的范围内；由运动校验，不合法的抛球被拒绝（400，什么都不发生）。
  不是发球方、或者发球窗口还没开、或者这一分已经抛过，都是 409。
- 抛球和动作一样有生效延迟（该项目的 act lead），在生效的那个控制步出现。
- 击球仍然是普通的 `act`，可以在抛球之前发出（先开始挥拍，再在算好的那一步抛球）。
- 机器人手里拿着拍子，没有空手，所以抛球是一个抽象（"手"或抛球装置）；它在各项目的 `[[deviations]]` 里写明。

## 2. 状态字段（三项相同）

| 字段 | 含义 |
|---|---|
| `you_serve` | 这一分你发球 |
| `you_receive_serve` | 这一分你接发球 |
| `serve.phase` | `waiting`（接发方还没准备好）、`open`（可以抛球）、`tossed`（已抛球，等发球方击球）、`done`（发球已完成或已判犯规） |
| `serve.court` | 这一分的发球区／发球格／半区，用该项目自己的叫法（羽毛球：`right` / `left`） |
| `serve.opens_in_s` | 离发球窗口打开还有多少秒（发球方） |
| `serve.deadline_in_s` | 离抛球截止还有多少秒（发球方） |
| `serve.tossed_at_step` | 抛球生效的控制步 |

`serve` 下面可以有项目自己的附加字段（例如网球的一发／二发）。

## 3. 计时与处罚

- 接发方准备好时（项目自己的延迟）发球窗口打开。
- 到 `deadline_in_s` 还没有抛球，算发球犯规（拖延）。
- 拖延的处罚（2026-10-08 定）：羽毛球和网球每一次拖延都算一次发球犯规（羽毛球：对方得分并得发球权；网球：算一次
  发球失误），不累计、不取消比赛资格；其他项目按各自规则书决定，并在 `sport.toml` 的偏离里写明。

## 4. 犯规的记法

比赛记录里因发球犯规而结束的一分，`how` 以 `serve_fault:<原因>` 开头，例如
`serve_fault:undue_delay: A did not toss the shuttle within 3 s ...`。原因用小写英文加下划线，各项目在
`sport.toml` 里列出自己的原因。接发方在发球完成前违例（如提前移动）用 `receive_fault:<原因>`。

## 6. 执行散布：每个选手一条独立的随机数流（2026-10-08 用户决定）

三项运动（以及所有有执行散布的项目，见 `docs/benchmarks/roboolympics-rules.md` A6）都按同一条规则：

- **一场比赛之内，两个选手的执行散布互相独立**：各自一条按种子生成的随机数流。不能再用"双方第 n 个动作用同一个随机数"
  （公共随机数）：后出手的一方能从对手第 n 个动作的偏差读出自己下一个偏差并提前补偿（2026-10-07 飞镖对战里四个模型都
  这样做了，每镖约多 16 分）。对脚本对手也一样：选手的流和脚本对手的任何随机抽取都不重合。
- **对战按"同一种子、先手互换"的两场成对进行，第二场两人交换随机数流**：流跟着角色走（例如流 1 = 先手/先发球方，流 2 =
  另一方），所以一对比赛下来双方遇到的运气完全相同。交换方式只由种子和"这是一对中的哪一场"（first_player）决定，是确定的。
- 有意共享的环境条件（风、同一个球场）照旧共享。
- 说明书里写明："each player's execution scatter is independent of the opponent's within a match; the two matches of a
  duel pair swap the scatter sequences"，不能再写"第 n 个动作散布相同"。

羽毛球已按此实现（revision wallclock-7 / duel-9：`bm.scatter_rng(seed, kind, stream, n)`，对战中先发球方流 1、另一方
流 2）；乒乓球的对战原本就按角色（先接发球方）分流；**网球**在合入 tennis-serve 时按同一规则实现（revision wallclock-9 /
duel-7，2026-10-09：`tn.scatter_rng(seed, kind, stream, n)`，对战中先发球方流 1、另一方流 2，成对比赛交换；单人比赛选手
流 1，键以 1000 开头，和脚本对手的抽取不重合），`sport.toml` 的 act 说明和 E11 写明。
