02 · Runtime and design

API facts versus the finite-control experiment

API FACT

  • Project pin exposes Hopper-v4, not current v5.
  • Action: Box(-1,1,(3,),float32) for thigh, leg, and foot torques.
  • Observation: (11,) float64.
  • Physics step: frame skip 4 × 0.002 s = 0.008 s, or 125 Hz.
  • RGB render: (480,480,3) uint8.
  • Default time limit 1,000; unhealthy height, angle, or state terminates earlier.
  • Reward is healthy + forward − control cost.

USER DECISION

  • Each joint torque takes one of {−1,0,+1}.
  • The Cartesian product creates 27 ordered actions.
  • Labels encode thigh/leg/foot as t_*, l_*, f_*; n/z/p mean negative/zero/positive.
  • All-zero action t_z_l_z_f_z is catalog ID 13 and the delayed no-op.
  • One policy observation per 125 Hz physics step.
  • Fixed L1=8 ms; native reward, reset, termination, observation, and rendering retained.

The runtime probe records the pinned API. The 27-vector catalog is explicitly marked user-approved because Gymnasium does not define this discretization.

10 · Isolation and limitations

Release boundary

  • The experiment changes Hopper's public action interface from continuous Box(3) to a user-approved 27-class catalog.
  • Catalog resolution is coarse: each joint has only −1, 0, or +1 torque.
  • The pinned task is Hopper-v4; current v5 fixes and metadata are not mixed in.
  • MuJoCo remains task-specific and is not added to base pyproject.toml.
  • Legacy environment paths remain untouched.
  • Only one seed and one latency were evaluated; observed return variance is substantial.
