02 · Runtime and design

Native Atari facts versus preprocessing decisions

API FACT

  • ALE/Asterix-v5, ALE 0.8.1, mode 0, difficulty 0.
  • Native action space Discrete(9): NOOP, UP, RIGHT, LEFT, DOWN, UPRIGHT, UPLEFT, DOWNRIGHT, DOWNLEFT.
  • Native observation and render: (210,160,3) uint8.
  • Each configured frameskip=1 step increments ALE episode frame by exactly one.
  • Asterix ROM uses NTSC timing: 60 raw frames/s.
  • Native reset starts at episode frame 0 with three lives.

FROZEN EXPERIMENT

  • Disable sticky actions with repeat probability 0.
  • Keep minimal nine-action catalog and native reward.
  • Use 1–30 seeded random NOOP actions at reset; do not add reward clipping, FireReset, or episodic-life termination.
  • Warp policy observation to 84×84 grayscale, then transpose to CHW.
  • Retain native RGB through env.render() for evaluation/video and possible later rollout.
  • Observe every four raw frames at 15 Hz; fixed L1=16.667 ms.

The runtime probe records the exact actions, screen, frame counter, modes, difficulties, and constructor kwargs. ALE does not publish render_fps for this ROM, so the NTSC 60 Hz clock is explicit contract data rather than a hidden fallback.

10 · Isolation and limitations

Release boundary

  • Asterix adds one task-owned observation wrapper; it does not modify generic adapter semantics or legacy Demon Attack.
  • The benchmark protocol is explicitly NTSC 60 Hz, frameskip 1, no stickiness, mode 0, difficulty 0.
  • Seeded random noop reset uses 1–30 native NOOP steps; no FireReset, EpisodicLife, or reward clipping is used.
  • Policy observation preprocessing changes the learning task to 84×84 grayscale CHW; native RGB is retained only for rendering and later handoff.
  • Only one seed, fixed L1, and deterministic evaluation protocol were run.
