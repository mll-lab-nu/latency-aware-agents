02 · Frozen environment contract

Official P2 timing, no action abstraction

Runtime API facts

  • Base id: myoChallengeTableTennisP2-v0.
  • Benchmark id: LatencyBench/MyoChallengeTableTennisP2-v0.
  • Action: Box(-1, 1, (275,), float32).
  • Observation: Box(..., (417,), float32).
  • MuJoCo timestep is 2 ms with frame skip 5, yielding 100 Hz.
  • Episode limit is 300 steps; native termination may happen sooner.

Benchmark decisions

  • env_fps: 100.0 and obs_fps: 100.0.
  • Latency queues whole 275-value vectors.
  • No-op is the native 275-value zero vector.
  • RGB uses the default camera at 224 × 224.
  • The wrapper seeds MyoSuite before P2 randomization so saved traces replay exactly.

03 · Contract propagation

The same action vector crosses every verified boundary

Sample Factory

A continuous Gaussian APPO head predicts the native Box(275) action.

Latency scheduler

Commands are issued at 100 Hz, delayed in raw 10 ms steps, then applied without clipping or remapping.

Teacher export

Canonical rows contain the applied 275-value action and rendered observation.

LeRobot

action_dim=275 and action_carrier=native. No StarVLA robot registration or mixture is emitted in this release.

04 · Trace visualization

Replayable dynamics and action timing

The MyoChallenge trace tool replays recorded applied actions from the same seed, verifies reward and done parity, writes a 100 FPS MP4, and plots ball/paddle position and speed, contacts, reward, solve state, muscle magnitude, pelvis commands, and issue/ready/apply times.

Install and run

python -m training.train \
  --config configs/examples/gymnasium/myochallenge_table_tennis_p2/small_model_train.yaml

  --config configs/examples/gymnasium/myochallenge_table_tennis_p2/small_model_eval.yaml

07 · Limits

What this release evidence does not establish

  • The smoke policies are not converged and did not solve P2.
  • One episode per latency is insufficient for statistical comparison.
  • No target-device latency profile was collected in this pass.
  • No VLA was fine-tuned, evaluated, or compared before and after latency-aware demonstrations.
  • The next experiment must train to convergence, collect target-device profiles, regenerate latency-aware demonstrations, and evaluate multiple seeds.
