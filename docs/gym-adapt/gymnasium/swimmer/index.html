02 · Frozen contract

Native action and state order, explicit MuJoCo 3 compatibility

Runtime facts

  • LatencyBench/SwimmerContinuous-v0, based on Gymnasium Swimmer-v4.
  • Current state: Box(-inf, inf, (8,), float64); policy observation: four stacked states, 32 values.
  • Action: Box(-1, 1, (2,), float32), first rotor then second rotor.
  • dt=0.04 s, frame skip 4, model timestep 0.01 s.
  • TimeLimit truncates at 1,000 steps; the base environment never terminates.

Adaptation decisions

  • All-zero two-dimensional pending action.
  • 25 Hz environment and observation clocks; latency remains measured in raw control frames.
  • placeholderained torque uses hold with FIFO action ordering.
  • The Gymnasium-v4 XML is preserved except for the removed collision="predefined" option rejected by MuJoCo 3.
  • Future rollout will save one current RGB image per row even though the teacher policy consumes four state frames.

06 · Limits and next experiment

Do not use this checkpoint as the final teacher yet

  • One seed was trained. The published reference uses seed 1111; this run uses the repository's standard seed 2222.
  • The latency-bench Gymnasium path and MuJoCo 3 compatibility XML preserve the declared contract but are not bitwise identical to the older published runtime.
  • All episodes reach 1,000 steps because Swimmer never terminates; return, not survival, is the relevant quality metric.
  • The next diagnostic should compare seed 1111 on this path and run a zero-latency action/reward parity trace against vendored mujoco_swimmer.
  • Teacher rollout and VLA training should wait until a small model approaches the published return scale. When rollout begins, use one current RGB image per row and omit stacked context images.
