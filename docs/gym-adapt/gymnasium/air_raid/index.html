02 · Runtime and design

Native Atari facts versus preprocessing decisions

API FACT

  • ALE/AirRaid-v5, ALE 0.8.1, mode 1, difficulty 0.
  • Native action space Discrete(6): NOOP, FIRE, RIGHT, LEFT, RIGHTFIRE, LEFTFIRE.
  • Native observation and render: (250,160,3) uint8.
  • Each configured frameskip=1 step increments ALE episode frame by exactly one.
  • AirRaid ROM uses PAL timing: 50 raw frames/s.
  • Reset starts at episode frame 8 with one life; AirRaid performs its own start behavior.

FROZEN EXPERIMENT

  • Disable sticky actions with repeat probability 0.
  • Keep minimal six-action catalog and native reward.
  • Training used no extra reset noops; the added reevaluation uses 1–30 seeded NOOP actions. Neither path adds reward clipping, FireReset, nor episodic-life termination.
  • Warp policy observation to 84×84 grayscale, then transpose to CHW.
  • Retain native RGB through env.render() for evaluation/video and possible later rollout.
  • Observe every four raw frames at 12.5 Hz; fixed L1=20 ms.

The runtime probe records the exact actions, screen, frame counter, modes, difficulties, and constructor kwargs. ALE does not publish render_fps for this ROM, so the PAL 50 Hz clock is explicit contract data rather than a hidden fallback.

10 · Isolation and limitations

Release boundary

  • AirRaid adds one task-owned observation wrapper; it does not modify generic adapter semantics or legacy Demon Attack.
  • The benchmark protocol is explicitly PAL 50 Hz, frameskip 1, no stickiness, mode 1, difficulty 0.
  • The published training contract keeps noop_max=0; a separate eval-only config sets noop_max=30, leaving the checkpoint and original result unchanged. Neither uses FireReset, EpisodicLife, or reward clipping.
  • Policy observation preprocessing changes the learning task to 84×84 grayscale CHW; native RGB is retained only for rendering and later handoff.
  • Only one seed, fixed L1, and deterministic evaluation protocol were run.
