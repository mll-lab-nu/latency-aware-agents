02 · Runtime reconnaissance

The installed API, not the newest web page

API FACT

  • Project pin: Gymnasium 0.29.1 and box2d-py 2.3.5.
  • Registered task: LunarLander-v2; the current documentation's v3 is unavailable in this runtime.
  • Action space: Discrete(4).
  • Observation: eight-dimensional float32 vector.
  • Clock: module and metadata both publish 50 Hz.
  • RGB render: (400,600,3) uint8.
  • Time limit: 1,000 steps; landing, crash, leaving viewport, or sleeping can terminate earlier.

FROZEN EXPERIMENT

  • Use discrete mode and preserve action values 0–3.
  • Action order: do nothing, left orientation engine, main engine, right orientation engine.
  • Use action 0 as the delayed queue's no-op.
  • Freeze gravity −10, wind disabled, wind power 15, turbulence 1.5.
  • Observe every 50 Hz raw tick and evaluate L1=20 ms.
  • Retain native observation, reward, reset, termination, and render behavior.

The exact runtime values are preserved in the API probe. The official page describes the same four action meanings, but its current v3 bounds and fixes must not be silently applied to this pinned v2 experiment.

04 · Immutable task contract

One native action catalog across every stage

observation_stride = 50 / 50 = 1 · latency_raw_frames = ceil(20 × 50 / 1000) = 1

Complete frozen env block
env:
  name: gymnasium
  task_name: lunar_lander_discrete
  env_id: LunarLander-v2
  registration_imports: []
  make_kwargs:
    render_mode: rgb_array
    continuous: false
    gravity: -10.0
    enable_wind: false
    wind_power: 15.0
    turbulence_power: 1.5
  env_fps: 50
  obs_fps: 50
  frame_stack: 1
  noop_action: do_nothing
  action_map:
    do_nothing: 0
    fire_left_orientation_engine: 1
    fire_main_engine: 2
    fire_right_orientation_engine: 3
  action_order:
    - do_nothing
    - fire_left_orientation_engine
    - fire_main_engine
    - fire_right_orientation_engine
  base_prompt: >-
    Land the spacecraft safely between the flags. Choose exactly one action from:
    do_nothing, fire_left_orientation_engine, fire_main_engine,
    fire_right_orientation_engine.

All four resolved configs produced identical env mappings. The scaffold-emitted copy is available as env_block.yaml.

05 · Contract propagation

How the native fast path is consumed

Gym factory

env.name=gymnasium selects the separate generic adapter and calls gym.make() with the frozen kwargs.

Sample Factory

The generic catalog exposes policy IDs 0–3 and stores task identity, values, no-op, prompt, and clock in the checkpoint.

L1 scheduler

Action 0 remains active until the first issued engine command becomes ready one raw tick later.

Latency-bench

The checkpoint ID is decoded through the same ordered catalog and passed unchanged to the native environment.

10 · Isolation and limitations

Release boundary

  • No task wrapper or new factory branch was added; this is the native Discrete(4) fast path.
  • Box2D remains a task-specific environment dependency and was not added to base pyproject.toml.
  • The pinned task is v2; current v3 fixes and wider observation bounds are not silently mixed in.
  • Legacy Flappy, Demon Attack, and Deadly Corridor paths remain untouched.
  • Only one seed, fixed L1, no wind, and one training budget were evaluated.
