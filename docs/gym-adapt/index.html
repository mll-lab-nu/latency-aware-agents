how to use this page

One worked example, two audiences

For a user: follow the adaptation from API probe to a verified latency-sensitive small-model experiment. Review the decisions and artifacts, then use the command ledger to continue teacher rollout, LeRobot conversion, basic OpenVLA SFT, and final evaluation. Commands marked NOT RUN are instructions, not claimed results.
For an adaptation agent: this page is both a process example and the required final-report format. A new adaptation should expose the same separation of API facts, user decisions, generated files, contract propagation, exact commands, linked evidence, continuation steps, isolation, and limitations.

The normative implementation guide is docs/gymnasium_adapter.md. This HTML page explains and evidences one execution of that guide; it does not replace the contract or authorize an agent to invent missing scientific choices.

01 / scope

The objective is a traceable adaptation, not an automatic claim

This is the release path for a Gymnasium task whose controller can be exposed as a finite, ordered catalog. It preserves the chosen Gymnasium construction, native observation, reward, terminated, and truncated, while the benchmark contributes a raw-step clock and an action scheduler.

Why InvertedPendulum is useful: its native action space is Box(shape=(1,)). A generic discrete small-model/OpenVLA pipeline cannot infer a meaningful discretization. The five forces below are an explicit user-owned experiment definition.

03 / API discovery

What an agent can obtain directly, before it asks the user anything

Version resolution is part of adaptation. The current official environment page documents InvertedPendulum-v5. The requested server pin, Gymnasium 0.29.1, does not register v5: the probe returned VersionNotFound: ... provides [v2, v4]. The agent surfaced this mismatch and the simulated user explicitly chose v4 rather than silently changing the dependency pin.

Direct probe

  1. Install the exact package/version in the experiment environment. The VLA environment must receive the same task package before a later SFT/eval run; that stage was not installed or run here.
  2. gym.make(id, render_mode="rgb_array"), then reset(seed=0).
  3. Read action/observation space type, shape, bounds, dtype, reset observation, unwrapped.dt, and one rendered RGB frame.
  4. Record the exact constructor arguments and raw API behavior. Do not infer an action vocabulary from Box bounds.

04 / transparent handoff

The agent stops at choices that an API cannot answer

Agent, after probing

The official page now describes v5, but your pinned Gymnasium 0.29.1 runtime raised VersionNotFound and offers v2/v4. The available v4 task has a continuous one-dimensional force in [−3, 3] at 25 Hz. Please decide whether to change the dependency or use v4, then choose a force catalog/order, safe no-op, native-vs-modified task semantics, observation rate, language objective, and budgets.

Simulated user decision for this example

Keep the reproducible Gymnasium 0.29.1 pin and use v4. Use five symmetric forces [-3,-1.5,0,1.5,3], with zero force as no-op. Preserve native observation/reward/termination. Treat every MuJoCo step() as a raw 40-ms frame and use observations at 25 Hz. Use the supplied balance prompt, L1 (40 ms), 1M RL steps, 200 rollout episodes, and basic 2,000-step OpenVLA SFT.

Agent, after confirmation

I will create a task-owned wrapper, freeze that exact catalog in four configs, verify zero-latency parity against the wrapped task, and keep the original legacy integrations untouched. I will not claim that the five-force catalog approximates the continuous optimum.

Wrapper core: a discrete ID becomes the exact native action
class InvertedPendulumDiscreteActionEnv(gym.Wrapper):
    def __init__(..., force_values, ...):
        env = gym.make(base_env_id, render_mode=render_mode, ...)
        super().__init__(env)
        self.force_values = force_values
        self.action_space = Discrete(len(force_values))

    def step(self, action):
        force = self.force_values[action]
        native_action = np.asarray([force], dtype=self.env.action_space.dtype)
        return self.env.step(native_action)

06 / baseline dataflow

One contract travels through every basic experiment

1. Evaluation adapter

factory.register_env_adapter("gymnasium") selects GymnasiumEnvAdapter. It imports registration_imports, calls gymnasium.make(env_id, **make_kwargs), passes action values to step(), and adds only benchmark metadata.

2. RL integration

training.gymnasium_sf.integration.build_cli_args_from_config() serializes the contract into Sample Factory arguments. make_gymnasium_sf_env() imports registration modules, applies GymnasiumActionCatalogWrapper, then GymnasiumActionLatencyWrapper. EnvClock and ActionScheduler use ID 2 as the configured zero-force no-op.

3. Teacher handoff

sf_teacher_config._rollout_task_contract() and _gymnasium_task_metadata() strictly restore the generic task from checkpoint fields. The exporter must not receive --env-name. It would write train/val parquet plus integration_name: gymnasium metadata.

4. VLA handoff and evaluation

latency_bench.envs.gymnasium_task.gymnasium_task_contract() materializes all 11 fields. Conversion would write an unpadded five-class one-hot carrier (active_action_dim=5), distinct from the original Box width 1. Generic StarVLA consumes rendered RGB only: include_state=false, so the small model's 4-D observation is not passed as VLA state. _validate_gymnasium_starvla_contract() strictly compares eval YAML, dataset manifest, and saved model config.

09 / separation and support boundary

The generic path is additive; legacy paths retain their own behavior

env.name: gymnasium is registered separately in latency_bench.envs.factory. Flappy Bird, Demon Attack, and Deadly Corridor retain their existing dedicated builders and training integrations. The generic project does not rewrite their action mappings, preprocessing, raw clocks, data exporters, or StarVLA configurations.

The measured relation L1 = 40 ms is specific to this accepted v4 clock (env_fps=25). A different Gymnasium task must probe and approve its own raw-tick meaning and rate; the agent must not copy 40 ms from this example.

Supported baseline path: Gymnasium five-value API; finite, ordered JSON-stable policy catalog; Sample Factory-compatible observation; rgb_array HWC render; one documented raw step(). A task-owned wrapper is the normal bridge when native actions are not JSON-stable.
Not a first-release claim: native continuous OpenVLA actions, automatic discretization, MultiDiscrete/MultiBinary generic VLA heads, policy frame stacks/RNN/memory experiments, generic GPU batched rendering, or multi-image/VLA variants.

10 / required agent deliverable

A new adaptation must end with an equally transparent report

Code generation is only part of an agent-assisted adaptation. The agent should create a self-contained report such as docs/gym-adapt/<task_name>.html, link it from docs/gym-adapt/README.md, reuse this page's information hierarchy and styles, and store curated evidence under docs/gym-adapt/assets/<task_name>/. The reference index.html must not be overwritten. Large checkpoints and raw experiment directories remain in ignored local or external storage.
