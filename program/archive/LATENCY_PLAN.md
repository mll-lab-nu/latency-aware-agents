# Balance 延迟 RL：按结果分支推进的实验计划                                                       
                                    
先回答“一帧延迟为什么学不会”，解决后再引入更长延迟、随机性和时间相关性。 实验按顺序推进；后面的诊 
断只有在前面的结果需要时才启动。                                                                  
                                                                                    
已有证据足以确定这个起点：固定一帧、100% 接纳时 teacher 已经明显失稳；10 FPS 实验接纳率达到约     
99%，训练后仍只存活约 38 步。因此第一轮继续研究随机丢请求，区分力不大。冻结对照、10 FPS 结果

## 1. 先查：探索噪声和第一次 PPO 更新，是否已经破坏了起点？                                              

### 怎么做              

先冻结权重，检查探索。 在零延迟下比较 teacher 的确定性动作与 PPO 实际采样动作，按 std=0.1 → 0.03 →       
0.01 顺序检查。选择能保留确定性 teacher 至少 80% 平均存活时间的最大 std；通过后停止继续试更小值。        
随后在固定一帧延迟下评测这个 std，记录它相对确定性 teacher 的影响。                                      

必须走真实训练中的采样、动作转换和 clipping 路径。改变 std 后重新采样，不能拿旧 logprob 冒充新策略       
的数据。                

再检查更新步幅。 零延迟和固定一帧各保存一个 16,384-transition rollout，以及更新前完整模型和              
optimizer。离线重放原生 PPO，先检查第一次 Adam 更新，再检查完整一次 rollout 的更新过程。                 

Actor LR 从 3e-7 开始：已有离线实验中，该值在 zero/temporal 两份数据上都完成了 64 次 actor 更新，        
且没有触发 target-KL 早停，但固定一帧的新数据仍需验证。已有步幅实验                                      

保留 target-KL 0.008。校准要求首次更新后的 admitted mean KL ≤0.008，全程 post-update mean KL             
≤0.02；不通过时只追加 1e-7 一个候选。这里检查更新后的 KL，因为 PPO clipping 和更新前 early               
stopping 都不保证下一步不会超调。Spinning Up in Deep RL+1                                                
(https://spinningup.openai.com/en/latest/algorithms/ppo.html?utm_source=chatgpt.com)

## 3. 若一帧仍学不会：检查 GAE 给出的动作改进方向是否可信                                                

### 怎么做              

复用实验 2 保存的策略和 rollout，先冻结 actor、critic、normalizer。                                      

对同一批行为数据比较两种 actor 学习信号：          

- **原 GAE：**保持 γ=0.99、λ=0.95。                
- **完整回报对照：**沿同一冻结随机策略补齐 episode，用实际后续回报减去同一个 value baseline。            

自然终止的轨迹使用完整 Monte Carlo 回报；time-limit 截断仍按原任务的 bootstrap 合同处理，并单独报        
告，不能称为纯 MC。续跑必须使用与训练一致的随机策略，不能拿确定性 continuation 检验另一个策略的价        
值。                    

这个对照针对的是 value bootstrap 带来的影响：GAE   
本身就在估计偏差与方差之间折中；更接近完整回报并不保证最终表现更好。arXiv                                
(https://arxiv.org/abs/1506.02438?utm_source=chatgpt.com)                                                

随后从同一模型和 optimizer snapshot 各做一次 actor 更新。比较时匹配实际 KL，而不是仅使用相同 LR：        
只在离线副本中缩放候选更新量，把两者限制在相同的、至多 0.004 的 admitted mean KL，再用独立种子评         
测。                    

作为方向检查，在同一完整环境状态中比较候选动作的 GAE 排序与独立续跑收益；不要把不同状态上的              
advantage 和 return 混在一起计算一个相关系数。最多检查三个不同的 on-policy 批次，避免用一次偶然更        
新定性。

## 4. 若学习信号仍解释不清：建立“一帧延迟可解决”的正对照                                                 

这一项包含两个有先后关系的小实验。                 

### 4A. 使用精确一步预测的 teacher                 

保持真实的一帧动作延迟、原 reset、原 noop 和 scheduler。                                                 

在时刻 t，根据已经确定将在当前物理步执行的旧 command，用模拟器副本预测下一步 observation，然后发         
出：                    

at​=πteacher​(o^t+1​).     

这个 command 仍然到下一帧才执行。预测必须包含 controller 内部状态，并验证预测的一步与真实环境下一        
步一致；复用已有重放能力，不只复制 qpos/qvel。     

这是一个有精确动力学帮助的诊断策略，不把它当成部署 actor 已经拥有的能力。 

### 4B. 仅当预测 teacher 成功时，尝试让现有小模型模仿它                                                  
                                                    
收集最多 16,384 条预测 teacher 的 issued-command 标签；输入严格使用当前合法的 H observation，不提        
供未来 observation。使用现有 actor、冻结 normalizer，按 episode 分训练/验证集，最多训练 2,000 个         
minibatch，batch 256、Adam LR 1e-4。               

先看独立数据拟合，再看闭环。若拟合好但闭环失败，只追加一轮、最多 16,384 条 student 访问状态上的          
oracle 标注，检查分布偏移。

## 执行与产物           

先安排 实验 1 → 实验 2。实验 3、4 是失败后的诊断分支，实验 5 是成功后的难度扩展。                        

复用现有 Balance harness、更新 snapshot、离线重放和因果干预工具；新增内容限制在实验入口，不引入通        
用训练框架或生产 API。每个实验使用独立输出目录，保存配置、模型、实际更新计数、逐局结果，以及“该结        
果支持什么／不能支持什么”。                        

训练、诊断续跑、评测的 transitions 分开计数。只有一个分支明确恢复平衡后，才以固定配方做三个              
training seeds 的确认；此前不启动 VLA 迁移或新的大规模参数网格。

### 当前结论

固定一帧要求策略依据当前物理 observation 和已经返回但尚未执行的 command 推断下一帧状态，再近似 `π_teacher(o_{t+1})`。精确 predictor 能恢复到 723 帧，而 λ=1 与 λ=.95 等效、现有 H actor 的受控 BC 又无法拟合和泛化该映射。当前证据把主要瓶颈定位在 **从合法 H 输入学习一步预测控制律的表示、拟合或状态覆盖**，不支持把 GAE λ、reward 索引、scheduler 或训练步数写成根因。一次 BC 失败仍不能证明 H 在信息论上不足；下一轮应先检查 H 是否包含决定接触后状态所需的完整信息，或直接提供可学习的预测状态，再谈更长延迟。
